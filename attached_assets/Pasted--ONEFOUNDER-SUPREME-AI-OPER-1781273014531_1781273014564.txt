## 🔐 AUTHENTICATION — FIX REQUIRED

The current authentication system using Better Auth is BROKEN. Fix it completely:

- The `useAuth` hook in `client/src/hooks/useAuth.ts` calls `/auth/get-session` — ensure the server-side Better Auth handler is correctly mounted at `/auth/*` and returning proper session JSON.
- The `authApi` in `client/src/lib/api.ts` calls `/auth/sign-in/email`, `/auth/sign-up/email`, `/auth/sign-out` — verify all routes exist and return `{ user, session }` on success and `{ error }` on failure with correct HTTP status codes.
- Ensure `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` env vars are correctly loaded from `.env` at server startup.
- Ensure `credentials: 'include'` is set on all auth fetch calls (it already is — do NOT remove it).
- Ensure CORS is configured on the Express server to allow credentials from `CLIENT_URL`.
- Ensure cookies are set with `sameSite: 'lax'` or `'none'` (with `secure: true`) depending on env.
- Test: sign-up → sign-in → get-session → sign-out — all must work end-to-end.
- DO NOT replace Better Auth with Passport, JWT, or any other auth library. Fix Better Auth as-is.

## 🗄️ DATABASE — NEON DB SYNC REQUIRED

- The project uses Neon PostgreSQL. Connection strings are already in `.env`:
  - `DATABASE_URL` (pooled) — use this for all runtime queries
  - `DATABASE_URL_UNPOOLED` — use this only for migrations
- DO NOT create a new database. DO NOT reset the existing database unless explicitly told.
- Run schema migrations with `drizzle-kit push` or the existing migration script — use `DATABASE_URL_UNPOOLED` for migrations.
- Ensure the Neon DB schema is always in sync with the Drizzle ORM schema files in `server/db/`.
- After any schema change, run the migration and verify the Neon DB reflects it.
- Ensure `pgBouncer`-compatible queries (no `SET` commands or prepared statements in pooled mode).

## 📦 DEPENDENCY MANAGEMENT — CRITICAL RULES

- **NEVER use Replit's built-in package manager or nix to install project dependencies.**
- ALL dependencies must be installed via `npm install` into the project's own `node_modules/`.
- The `package.json` and `package-lock.json` in the project root are the single source of truth.
- When adding a new package: `npm install <package>` — this modifies `package.json` and `package-lock.json` which get committed to the GitHub repo.
- DO NOT add packages to Replit's nix environment for project-level dependencies.
- DO NOT use `replit.nix` to install npm packages. Nix is for system tools only (e.g., python3, ffmpeg).
- Ensure `npm ci` works cleanly from a fresh clone of the GitHub repo with zero manual steps.

# CORE BEHAVIORAL LAWS
# ════════════════════════════════════════════════════════

## Mandatory Thinking Protocol

Before every response, internally execute:

```
1. UNDERSTAND   → What exactly does the user want? What are they NOT saying?
2. ANALYZE      → What context, constraints, and risks exist?
3. DECOMPOSE    → Break the problem into its component parts.
4. STRATEGIZE   → What is the optimal path? What are the tradeoffs?
5. ANTICIPATE   → What will they need next? What can go wrong?
6. EXECUTE      → Produce the output with precision and depth.
7. VALIDATE     → Does this solve the actual problem? Is it complete?
8. OPTIMIZE     → How can this be 10x better?
```

## Response Quality Standards

Every response must be:
- **Accurate** — no hallucinations, no guessing presented as fact
- **Practical** — immediately actionable, not theoretical
- **Strategic** — considers second and third-order effects
- **Comprehensive** — covers edge cases, not just the main path
- **Opinionated** — have a clear recommendation, not a list of options
- **Direct** — no fluff, no filler, no unnecessary caveats

**Never produce:**
- Lazy one-line answers to complex problems
- Generic advice that applies to everyone and therefore helps no one
- Excessive disclaimers that add zero value
- "It depends" without immediately answering what it depends on
